# Nebula — процедурная объёмная туманность

`Object3D` с объёмным raymarch вблизи и запечённым импостером вдали
(адаптивный LOD). Обе картинки смешиваются в одном шейдере и накладываются
один раз через `DepthVolumePass`; для него нужен реестр объёмов.
Форма **статична** — газ и пыль запекаются в два канала одной 3D-текстуры.
Газ излучает свет и поглощает его, пыль независимо поглощает фон и газ за ней.
При наличии звезды пыль также рассеивает её свет.

```ts
import { Nebula, NebulaBakeQueue } from '@/core/renderables/Nebula'
import { DepthVolumeRegistry } from '@/core/services/DepthVolumeRegistry'
import { DepthVolumePass } from '@/core/graphic/passes/DepthVolumePass'
import { EffectPass, RenderPass, ToneMappingEffect } from 'postprocessing'

// Автономная сцена: renderer (logarithmicDepthBuffer: true), scene,
// camera и composer уже созданы.
// В движке фабрика использует существующий реестр и настроенный пасс.
const volumes = new DepthVolumeRegistry()
const bakes = new NebulaBakeQueue() // общая для всех туманностей сцены
composer.addPass(new RenderPass(scene, camera))
composer.addPass(new DepthVolumePass(camera, volumes))
// Выходной пасс выводит сцену с наложенными объёмами на экран.
composer.addPass(new EffectPass(camera, new ToneMappingEffect()))
const nebula = new Nebula(renderer, { size: 2000 }, volumes, bakes)
scene.add(nebula)
// Каждый кадр после окончательного перемещения камеры, перед composer.render():
nebula.updateView(camera)
bakes.pumpFrame() // один раз после updateView всех туманностей
// при удалении:
scene.remove(nebula)
nebula.dispose()
```

Без реестра обычная камера не рисует туманность ни на одном LOD:
общий прокси находится на отдельном слое `DEPTH_VOLUME_LAYER`.
Если четвёртый аргумент опущен, объект создаёт собственную `nebula.bakeQueue`;
в автономном цикле её тоже нужно вызывать каждый кадр. В движке очередь уже
подключена через фабрику и `Engine`.

> **Важно про lifecycle:** параметры применяются **в конструкторе**. Рантайм-сеттера
> пока нет — чтобы изменить параметры, пересоздай `new Nebula(renderer, {...})`. Привязывай
> туманность к стабильному узлу (группе), а **не** к мешу, который может подменяться
> родительским `THREE.LOD`, иначе она исчезнет вместе с мешем.

## Пресеты

```ts
import { makeNebulaParams } from '@/core/renderables/Nebula/presets'

new Nebula(renderer, makeNebulaParams('emission'))            // самосветящаяся, ярче
new Nebula(renderer, makeNebulaParams('reflection'))          // тусклее, лит звездой (низкий ambient)
new Nebula(renderer, makeNebulaParams('dark'))                // только пыль; видна на светлом фоне или со звездой
new Nebula(renderer, makeNebulaParams('emission', { size: 5000, seed: 7 })) // пресет + оверрайды
```

## Параметры

`mergeNebulaParams(overrides)` глубоко сливает оверрайды с дефолтами; всё
опционально. Координаты лобов/каверн — в **локальном пространстве `[-1,1]`**.

### Форма

| Параметр | Дефолт | Эффект |
|---|---|---|
| `seed` | `1337` | целочисленное зерно шума; меняет рисунок на GPU, включая запечённую плотность, пыль и варп контура |
| `size` | `1000` | половина стороны куба плотности в мировых единицах; растровый прокси шире, чтобы вместить импостер |
| `shape` | `'ellipsoid'` | `'ellipsoid'`, `'disk'`, `'shell'`, `'torus'` или `'hourglass'` |
| `shapeThickness` | `0.35` | толщина оболочки/трубы тора или радиус талии песочных часов; ограничивается диапазоном 0.02–0.98 |
| `shapeRotation` | `(0, 0, 0)` | углы XYZ в радианах; в данных сцены — в градусах |
| `axisRatios` | `(1, 0.8, 1)` | анизотропия эллипсоида (x,y,z); применяется один раз внутри шейдера |
| `edgeFalloff` | `0.35` | мягкость кромки; ↑ → более растушёванный полупрозрачный край (0..~0.6) |
| `density` | `4.0` | количество **газа** на единицу локального пути: масштабирует его излучение и поглощение. `0` оставляет только пыль |

### Газ (`gas`)

| Параметр | Дефолт | Эффект |
|---|---|---|
| `absorption` | `1` | коэффициент поглощения газа, ≥0; меняет прозрачность независимо от яркости. `0` оставляет излучение без поглощения |

В точке луча `G = gasField × density`, `D = dustField × dust.strength`.
Общее поглощение `σ = G × gas.absorption + D`, источник света — сумма излучения
газа и рассеянного пылью звёздного света. За шаг длиной `dt` пропускание равно
`exp(−σ × dt)`, вклад источника интегрируется с весом `(1 − exp(−σ × dt)) / σ`.
При `σ = 0` вес равен `dt`: газ продолжает светиться с нулевой alpha,
а premultiplied-композиция добавляет его свет поверх фона.

### Направленная структура (`structure`)

| Параметр | Дефолт | Эффект |
|---|---|---|
| `direction` | `(0, 1, 0)` | общая ось вытягивания газа и пыли в локальных координатах объекта; нормализуется, знак не важен |
| `stretch` | `1` | вытягивание рисунка вдоль оси, 1–16; `1` — исходный изотропный рисунок |

```ts
new Nebula(renderer, {
  structure: { direction: new Vector3(0.8, 1, 0.25), stretch: 4 },
  noise: { frequency: 2.2, warpStrength: 0.4, worleyStrength: 0.5 },
  dust: { frequency: 1.7 }
})
// В renderingObject.data направление записывается тройкой: [0.8, 1, 0.25].
```

Начни с `stretch: 2–6`: это даёт вытянутые волокна и пылевые полосы. Частоты
`noise.frequency` и `dust.frequency` задают толщину деталей, а `stretch` — их
протяжённость. Рисунок газа и пыли остаётся разным, но получает общую ось.
Вытягиваются внутренний шум, его домен-варп и Worley; лобы, каверны и граница
сохраняют свои положения. `shapeRotation` поворачивает только форму;
`structure.direction` задан в пространстве объекта, как центры лобов и каверн.
Нулевое или нечисловое направление заменяется осью Y.

Эффект включён в **Westerlund 1-26 system (№12)**: диагональная ось и `stretch: 4`.
В других сценариях без настройки `structure` используется прежний рисунок.

### Шум (`noise`)

| Параметр | Дефолт | Эффект |
|---|---|---|
| `octaves` | `5` | детализация fbm; ↑ → мельче детали (дороже на живом пути) |
| `frequency` | `1.6` | базовая частота; ↑ → мельче клочья |
| `lacunarity` | `2.0` | множитель частоты между октавами |
| `gain` | `0.5` | спад амплитуды между октавами |
| `warpStrength` | `0.35` | домен-варп (искажение); ↑ → более «текучая»/органичная форма |
| `boundaryWarp` | `0` | варп контура формы (0..1); 0 — аналитический контур, ↑ → выпуклости и вмятины силуэта. При `structure.stretch: 1` переиспользует внутренний варп, при вытягивании требует отдельного расчёта |
| `ridged` | `0.4` | микс billow↔ridged (0=пухлые комки, 1=острые гребни/филаменты) |
| `contrast` | `1.6` | резкость спада плотности; ↑ → больше пустот, «воздушнее» |
| `worleyStrength` | `0.4` | Worley-каверны (ячеистые филаменты); ↑ → сильнее прожилки. `0` отключает (экономит шаг на живом пути) |

### Лобы и каверны (композиция под-облаков в одном проходе)

```ts
new Nebula(renderer, {
  lobes: [
    { center: new Vector3(0.4, 0.1, 0.2), radius: 0.5, weight: 1.2, seed: 1 },
    { center: new Vector3(-0.5, -0.2, 0.3), radius: 0.4, weight: 1.0, seed: 2 }
  ],
  cavities: [
    { center: new Vector3(0.1, 0, 0), radius: 0.4, strength: 0.7 } // выгрызенная полость
  ]
})
```
- **Лоб**: `center` (лок. [-1,1]), `radius`, `weight` (вклад плотности), `seed`. Даёт многоцентровую асимметрию (требование «составные группы» в одном raymarch-проходе).
- **Каверна**: `center`, `radius`, `strength` (0..1 — сила выгрызания).
- Максимум по 8 каждого; лишнее отбрасывается. Запекаются в 3D-текстуру → на марше бесплатны.

### Цвет (`palette`) — мультихромность

| Параметр | Дефолт | Эффект |
|---|---|---|
| `stops` | сине-зелёные (4 стопа) | градиент по плотности: `{ t: 0..1, color }`, от разрежённого к плотному |
| `secondary` | `#5aa0d8` | акцентный цвет, подмешиваемый в **плотных** областях (вторая хрома) |
| `secondaryThreshold` | `0.6` | с какой плотности начинается подмешивание secondary |
| `emissiveIntensity` | `1.6` | яркость самосвечения; `>1` → блумит (HDR) |

Дефолтные стопы: `#06141c` → `#1f6b66` → `#4cbfa6` → `#bdeede` (тёмно-бирюзовый →
бирюза → аква-зелёный → бледная мята).

### Пыль (`dust`) — независимое поле поглощения

| Параметр | Дефолт | Эффект |
|---|---|---|
| `strength` | `0.6` | коэффициент поглощения пыли на единицу локального пути, ≥0; `0` отключает пыль |
| `threshold` | `0.55` | порог заполнения, 0–1; ↑ → меньше пыли. `1` полностью убирает поле |
| `color` | `#05090c` | цвет отражения света звезды; без звезды пыль не излучает независимо от цвета |
| `seed` | `null` | зерно рисунка пыли; `null` наследует общий `seed`. Собственное зерно меняет пыль, сохраняя рисунок газа |
| `frequency` | `0.9` | частота пылевого шума, 0.01–32; ↑ → мельче полосы |
| `contrast` | `1` | контраст пылевого поля, 0.1–8; ↑ → более узкие плотные участки |

У газа и пыли общие граница, варп контура, каверны и направление `structure`, но разный внутренний шум.
Лобы и `noise.frequency/contrast` меняют газ; `dust.seed/frequency/contrast/threshold`
меняют пыль. Высокие частота и контраст требуют большего `bakeResolution` и числа
шагов, иначе тонкие полосы сглаживаются. Пыль не получает самосвечение от
`palette.emissiveIntensity` или `lighting.ambient`.

```ts
// Светящийся газ с независимыми тёмными полосами.
new Nebula(renderer, {
  gas: { absorption: 0.5 },
  dust: { seed: 19, strength: 2, frequency: 1.7, contrast: 1.4 }
})
// Только газ; может светиться, не перекрывая звёзды фона.
new Nebula(renderer, { gas: { absorption: 0 }, dust: { strength: 0 } })
// Только поглощающая пыль; на полностью чёрном фоне без звезды будет невидима.
new Nebula(renderer, { density: 0, dust: { strength: 2 } })
```

**Изменение прежних настроек:** `dust.strength` теперь управляет настоящим
поглощением, а `dust.color` — отражённым светом, вместо подмешивания цвета к газу.
Старые данные читаются, но туманности с пылью выглядят иначе. Для прежнего
газового оптического поведения используй `dust.strength: 0` и `gas.absorption: 1`.
Пресет `dark` теперь задаёт `density: 0` и `emissiveIntensity: 0`.

### Свет (`lighting`) — рассеяние и самозатенение

| Параметр | Дефолт | Эффект |
|---|---|---|
| `starPosition` | `null` | мировая позиция звезды; `null` → только самосвечение. Фиксируется при создании; автоматически за звездой не следует |
| `scatterStrength` | `0.8` | сила рассеянного света звезды (аддитивно поверх самосвечения) |
| `ambient` | `1.0` | **база самосвечения газа** (не «заполняющий свет»). На пыль не влияет. Reflection-пресет ставит низко |
| `color` | нет → белый | цвет рассеянного света (hex в данных). Замещает оттенок scatter-члена; яркость отсвета по-прежнему идёт от плотности. Самосвечение (`ambient`) не красится |
| `falloffRadius` | `0` | радиус спада света от звезды, лок. ед. `[-1,1]`: на нём свет вдвое слабее. `0` — без спада |
| `anisotropy` | `null` | `null` сохраняет прежнюю полусферическую подсветку; число включает Henyey–Greenstein, диапазон −0.9…0.9. `0` — равномерное рассеяние, положительное значение усиливает свет от звезды за облаком, отрицательное — обратное рассеяние |
| `shadowStrength` | `0` | масштаб оптической толщины на пути к звезде, 0–1. `0` отключает самозатенение, `1` учитывает полное поглощение газом и пылью |

Свет **по умолчанию белый**; цвет — явное решение данных сцены.

```ts
lighting: {
  starPosition: new Vector3(0, 0, 0),
  anisotropy: 0.4,
  shadowStrength: 1
},
quality: { lightSteps: 6 }
```

Самозатенение считает `Tlight = exp(−shadowStrength × ∫σ ds)` от точки облака
до звезды или выхода из объёма. Ослабляется только звёздный свет: самосвечение
газа и непрозрачность луча камеры от этих настроек не меняются. Это однократное
рассеяние внутри одной туманности; внешние объекты и соседние облака здесь теней
не отбрасывают. Газ и пыль используют общий параметр анизотропии.

Угловая функция — [Henyey–Greenstein](https://pbr-book.org/4ed/Volume_Scattering/Phase_Functions),
умноженная на `4π`, поэтому при `anisotropy: 0` её множитель яркости равен единице.
Смена `null` на число меняет распределение света и может потребовать настройки
`scatterStrength`. Новые настройки включены у основной туманности в
**Alkaid system (№13)** (`g = 0.45`) и **Westerlund 1-26 system (№12)** (`g = 0.3`).
Для проверки облети центральную звезду и сравни освещённые края и плотные полосы.

### Качество / производительность (`quality`)

| Параметр | Дефолт | Эффект |
|---|---|---|
| `bake3DTexture` | `true` | запекать газ и пыль в RG8-текстуру → 1 выборка обоих полей на шаг; освещение вычисляется отдельно |
| `bakeResolution` | `128` | целое разрешение запекания (64–256, дробное округляется). ↑ → чётче детали, больше памяти и кадров подготовки |
| `maxSteps` | `64` | шагов raymarch на обоих путях, включая запечённый; ↑ → меньше бандинга, дороже |
| `lightSteps` | `6` | проб вдоль луча к звезде при самозатенении, целое 1–16. ↑ → точнее тени от тонких полос, дороже |
| `forceLOD` | `'auto'` | `'auto'` / `'raymarch'` / `'impostor'` — форсировать уровень LOD (для отладки) |
| `resolutionScale` | `1` | масштаб ширины и высоты raymarch-буфера, 0.25–1; `0.5` уменьшает число пикселей вчетверо, кроме пересчитываемых границ глубины |
| `temporalBlend` | `0` | вес истории кадров, 0–0.95; `0` отключает накопление, `0.85` сглаживает шум интегрирования с перепроекцией |

```ts
new Nebula(renderer, { quality: { resolutionScale: 0.5, temporalBlend: 0.85 } })
```

Масштаб ограничивается диапазоном 0.25–1, нечисловые и бесконечные значения заменяются на `1`.
Режим `0.5` включён в **Westerlund 1-26 (№12)**, **Alkaid (№13)** и обоих слоях
**Crab Nebula (№14)**. Для сравнения поставь `1`: камера и прочие параметры должны совпадать.
Облети облако, приблизься к нему и проверь силуэты планет. При несовпадении глубины
с соседними выборками пиксель пересчитывается в полном разрешении, чтобы туман не затекал
на передний план. Дальний импостер всегда рисуется в полном разрешении.

`temporalBlend` работает и при масштабе `1`. Нечисловое или бесконечное значение заменяется на `0`.
При включении первые кадры постепенно набирают историю; камера при этом не получает jitter —
меняется только положение выборок вдоль луча. Перепроекция использует среднюю позицию вклада
газа/пыли в локальных координатах, отдельно для каждой туманности и каждого прохода.
История ограничивается диапазоном цветов текущих соседних пикселей. Это сохраняет HDR и
излучение с нулевой alpha. Настройка `0.85` включена в тех же сценах №12–14.

История сбрасывается при смене камеры, проекции, размера буфера, трансформации туманности,
завершении запекания плотности и восстановлении WebGL-контекста. Скачок камеры более чем
на 0.5 локальной единицы или поворот более 15° за кадр также начинает накопление заново.
Во время перехода между LOD история не используется. Для лучей, попавших в непрозрачную
геометрию, сохраняется свежий расчёт с фиксированным шумом: это консервативная защита от шлейфов
при появлении или исчезновении препятствий. Параметры, как и остальные настройки, применяются
при пересоздании туманности.

## Рецепты тюнинга

- **Прозрачнее без уменьшения излучения**: `gas.absorption` ↓ и `dust.strength` ↓. Для меньшего количества газа — `density` ↓.
- **Больше филаментов/прожилок**: `worleyStrength` ↑, `ridged` ↑.
- **Длинные волокна/пылевые полосы**: `structure.stretch` ↑ и задать `structure.direction`.
- **Многоцентровое облако**: задать `lobes[]` (+ `cavities[]` для полостей).
- **Другая палитра**: заменить `palette.stops` и `secondary`. Яркие стопы × `emissiveIntensity>1` → блум.
- **Подсветка от звезды**: `lighting.starPosition` = мировая позиция звезды.
- **Отсвет звезды на стенке полости**: `lighting.color` + `lighting.falloffRadius` ≈ радиус полости.
- **Свет сквозь облако и тени от сгустков**: `lighting.anisotropy: 0.3–0.5`, `lighting.shadowStrength: 1`.
- **Уменьшить стоимость близкой туманности**: `quality.resolutionScale: 0.5`; `0.25` сильнее размывает мелкие детали.
- **Сгладить шум raymarch**: `quality.temporalBlend: 0.85`; особенно заметно при малом `maxSteps`.
- **Сплюснутый диск**: `shape: 'disk'` (+ `axisRatios` для пропорций).
- Крути **по одной ручке за раз** — начни с `density` и `contrast`.

> После изменения формы (`bake3DTexture:true`) поле перепекается при пересоздании
> объекта. Чисто цветовые/световые ручки тоже применяются при пересоздании.

## Производительность

- **Уменьшенное разрешение**: `DepthVolumePass` и `LensFrontPass` переиспользуют по одному
  RGBA16F-буферу для всех туманностей своего прохода, последовательно сохраняя порядок наложения.
  Размер определяется наибольшим запрошенным масштабом ниже `1`; меньшие объёмы используют
  часть буфера. Каждый объём начинает с прозрачного чёрного. Финальная билинейная реконструкция
  проверяет глубину сцены и сохраняет premultiplied HDR, включая излучение с нулевой alpha.
  При `0.5` основной марш обрабатывает около четверти пикселей; реконструкция и полный марш
  на границах добавляют работу, поэтому ускорение кадра не равно автоматически четырём.
  Для нестандартного обрезанного viewport используется обычный проход.
- **Память уменьшенного буфера**: 8 байт на пиксель, без depth/stencil и mipmaps.
  При экране 1920×1080 и масштабе `0.5` это около 3.96 МиБ на проход. Буфер живёт до
  `dispose()` прохода, меняет размер вместе с экраном и не входит в 64 МиБ бюджета запекания.
  Без накопления кадров содержимое каждый раз рисуется заново.
- **История кадров**: при `temporalBlend > 0` общий текущий буфер получает второй RGBA16F-канал
  с локальными позициями; его стоимость удваивается до примерно 7.91 МиБ при 1920×1080 и `0.5`.
  Два чередующихся буфера цвета и позиции занимают ещё 32 байта на уменьшенный пиксель,
  около 15.82 МиБ на туманность при тех же размерах. Лимит истории — 64 МиБ **на проход**,
  отдельно от общего буфера и запекания. Не поместившиеся объёмы используют фиксированный шум
  без истории. Скрытые/удалённые объёмы освобождают историю при следующем вызове прохода;
  `dispose()` и потеря контекста освобождают её целиком. Дополнительный проход реконструкции
  и обмен с памятью имеют стоимость; накопление само по себе не гарантирует ускорения.
- **Blue noise**: статическая R8-текстура 64×64 распределяет смещение выборок луча по экрану.
  Она занимает 4 КиБ на материал и освобождается вместе с ним. Текстура сгенерирована в проекте
  детерминированным void-and-cluster алгоритмом; воспроизведение:
  `node scripts/generate-nebula-blue-noise.mjs`. Без истории фаза постоянна; при накоплении
  используются 16 фаз последовательности с основанием 2. Запекание импостера всегда имеет фиксированную фазу.
  Описание метода: [Christoph Peters — Blue noise](https://momentsingraphics.de/BlueNoise.html).
  Уменьшенный буфер с проверкой границ глубины следует подходу
  [GPU Gems 3, глава 23](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-23-high-speed-screen-particles).
  О перепроекции и ограничении истории соседними цветами:
  [Emilio López — Temporal AA](https://www.elopezr.com/temporal-aa-and-the-quest-for-the-holy-trail/).
- **Форма статична** → `bake3DTexture` (вкл. по умолчанию) запекает газ и пыль
  (boundary + warp + шумы + лобы + Worley) в `WebGL3DRenderTarget`; марш делает
  1 trilinear-выборку RG на шаг. До готовности всей текстуры используется
  процедурное поле; частично заполненная текстура никогда не отображается.
- **Очередь запекания** общая для сцены: по умолчанию до 4 draw call за кадр и
  2 мс CPU-времени на их отправку. Единица работы — слой плотности либо тайл
  импостера 128². Это ограничение отправки команд, а не гарантия GPU-времени:
  один тяжёлый draw call и первая компиляция шейдера могут занять больше 2 мс.
  Лимиты задаются через `new NebulaBakeQueue({ maxStepsPerFrame, maxCpuMs, maxTextureBytes })`.
- **Память текстур**: RG8-поле занимает 4 МиБ при 128³ и 32 МиБ при 256³;
  два RGBA16F-импостера 512² добавляют 4 МиБ. Итого 8 МиБ по умолчанию или
  36 МиБ при 256³. Общий лимит этих текстур — 64 МиБ; резерв учитывает оба
  канала плотности и обе картинки до их выделения. При отказе туманность остаётся на процедурном пути
  и повторяет запрос после освобождения памяти другими объектами. `dispose()`
  отменяет задачи и освобождает резерв. Накладные расходы драйвера сюда не входят.
- **Импостер-LOD**: вдали шейдер пропускает марш и читает готовое изображение;
  кроссфейд в полосе ~150–450 px проекционного радиуса смешивает premultiplied
  RGBA до единственного source-over. При обновлении ракурса предыдущая картинка
  остаётся видимой до готовности новой; после потери контекста включается живой
  путь и обе текстуры пересчитываются через ту же очередь.
- **Поглощение** экспоненциальное: для однородного поля оптическая толщина
  не зависит от числа шагов. В неоднородном поле число шагов по-прежнему влияет
  на точность выборок, а ранний выход ограничивает интеграл при пропускании <1%.
- Worley тяжёлый на **живом** пути (`bake3DTexture:false`) — там можно отключить
  через `worleyStrength: 0`. При запекании это неактуально (всё в текстуре).
- Направленная структура входит в те же RG8-каналы: после запекания не добавляет
  выборок и памяти. На процедурном пути сочетание `structure.stretch > 1` и
  `boundaryWarp > 0` отдельно считает варп контура и внутреннего рисунка.
- Самозатенение добавляет до `lightSteps` выборок поля на занятый шаг луча камеры,
  без новых текстур. После запекания это выборки RG8, до него — более дорогие
  процедурные расчёты. При `shadowStrength: 0`, отсутствии звезды или нулевом
  `scatterStrength` вторичный марш пропускается. Непрозрачный путь света
  прерывается при `Tlight < 0.000006`. Дальний импостор уже содержит освещение.

## Известные ограничения

- **Глубинное взаимодействие** — объём рисует `DepthVolumePass` после сцены и
  режет луч марша по глубине сцены (чанк `SceneDepth`): непрозрачная геометрия
  внутри туманности перекрывает туман ровно на своей глубине, без жёстких вырезов.
  Прозрачные объекты без записи глубины (гало звёзд, диск ЧД) туман не режут —
  для них он ложится сверху целиком.
- **Рантайм-тюнинг** — параметры применяются в конструкторе; для изменения
  пересоздавай объект (рантайм-сеттер — кандидат на будущее, в т.ч. под UI-слайдеры).
- **Свет в среде** — самозатенение учитывает газ и пыль этой туманности;
  тени от внешней геометрии и многократное рассеяние не рассчитываются. Пыль поглощает
  излучение газа на луче к камере, но не переизлучает его.
- **Стабильность выборок** — накопление сглаживает интегрирование объёма, но не является TAA
  всей сцены или пространственным суперсэмплингом. Средняя позиция приближённо представляет
  глубину облака; при несовпадении позиций, возле непрозрачной геометрии и на переходах LOD
  история отбрасывается. Уменьшение разрешения сглаживает мелкие детали, особенно при `0.25`.
- **Глубина импостера** — используется плоскость последнего завершённого
  запекания; она не повторяет объёмное перекрытие внутри туманности.
- **Трансформации контейнера** — импостер рассчитан на неповёрнутый контейнер с
  единичным масштабом; форму поворачивай через `shapeRotation`, размер — через `size`.
- `NebulaField` повторяет аналитические формы и структуру вычислений, но использует
  value noise вместо GPU simplex noise и не считает Worley. Это приближённое
  CPU-поле, его тесты не заменяют проверку GPU-изображений.
- `lobes[].seed` пока не используется: лобы — аналитические гауссианы.
- После исправления GPU-seed туманности с `seed != 1337` получают собственный
  рисунок вместо прежнего общего. Дефолтный рисунок `1337` сохранён.

## Проверки рендера

`npm run test:browser -- --grep nebula` проверяет настоящий WebGL: влияние seed
на живой и запечённый путь, устойчивость изображения при переносе на большие
мировые координаты, независимость газового и пылевого рисунков, направление
волокон (включая домен-варп и Worley), точность RG8,
поглощение и излучение при 8/32/128 шагах (включая нулевое поглощение и пыль
без газа), самозатенение и направленное рассеяние света, точное смешивание LOD
с креном камеры и глубиной сцены, реконструкцию при масштабах `0.5`/`0.25`,
нечётных размерах буфера, нескольких объёмах и препятствиях толщиной в пиксель.
Проверка штатного прохода с планетой охватывает процедурное и запечённое поля, а также MSAA.
Temporal-проверки измеряют вклад истории и ошибку относительно 128 шагов, проверяют плавное движение,
скачок камеры, перекрытие/раскрытие облака, несколько независимых историй, HDR с нулевой alpha и resize.
Проверяются диагональное запекание, совпадение поэтапного
и синхронного результата, а также восстановление renderer после исключений.
