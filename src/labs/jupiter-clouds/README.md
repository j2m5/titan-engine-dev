# Юпитер: лаборатория объёмных облаков

Эксперимент перед интеграцией облаков в основной многопланетный рендер TitanEngine.

## Запуск

```sh
npm install
npm run dev -- --port 8086
```

Открыть **http://127.0.0.1:8086/cloud-lab.html**. Страница также входит в production build как `cloud-lab.html`.
Основной вход `index.html` продолжает запускать обычное приложение. Для лаборатории не нужны `.env`, S3,
текстуры из `storage/images` и внешние CDN.

- Пять положений камеры: орбита (90 000 км), переход (580 км), над слоем (45 км), внутри (20 км), под слоем (5 км).
- Кликнуть по сцене: WASD — полёт, Q/E — радиальное движение, Shift — ускорение.
- Перетаскивание левой кнопкой — обзор; колесо — движение вперёд/назад.
- Облака можно выключить для сравнения, сменить качество и угол Солнца.
- Вдали используется исходная текстура Юпитера. Облака и их тени не рассчитываются дальше 1 000 км над верхом слоя.
  Между 1 000 и 100 км объём плавно проявляется; ближе 100 км виден полностью. Обе дистанции настраиваются в панели.
  Текстура остаётся основой во всём диапазоне, а объём при приближении дополняет её; плотные облака вблизи могут её закрывать.
- «Кадр» показывает сглаженный интервал кадров целиком, включая браузер/VSync; это не GPU timer query.

## Что переиспользуется

- `@takram/three-clouds` **0.7.6**: марш облаков, процедурные 3D-текстуры формы, освещение, тени и временное восстановление.
- `@takram/three-atmosphere` **0.19.1**: композиция облачного overlay и воздушной перспективы.
- `@takram/three-geospatial` **0.9.1**: эллипсоид и вспомогательная математика.
- TitanEngine: конфигурация атмосферы Юпитера (`actorId: 49`) и `AtmosphereLUTGenerator` с четырьмя порядками рассеяния.
- Поверхность: точная копия существующего ресурса `32`, `planets/jupiter/jupiter.jpg`, из хранилища проекта
  (`https://storage.yandexcloud.net/textures/planets/jupiter/jupiter.jpg`). Она включена в `assets/jupiter.jpg`,
  чтобы лаборатория и production build работали без сетевого доступа к хранилищу. Карта читается как sRGB, без цветового множителя.

Takram: [three-geospatial](https://github.com/takram-design-engineering/three-geospatial), MIT, Shota Matsuda.
Текст лицензии включён в `public/licenses/takram-three-geospatial.txt`.

## Адаптация масштаба

Сцена измеряется в метрах, конфигурация и LUT Bruneton — в километрах. Адаптер переводит только радиусы;
коэффициенты рассеяния и профили плотности уже имеют нужные единицы. Начало сцены находится на датуме
Юпитера; `worldToECEFMatrix` переводит координаты в систему планеты.

1. Вместо WGS84 высота камеры вычисляется относительно сферы Юпитера (радиус 69 911 км).
2. Удалены стандартные земные слои; остался один слой 10–30 км с постоянной картой покрытия.
3. Дальность и начальный шаг марша адаптированы к наблюдению с орбиты.
4. `planetDepth.ts` декодирует логарифмическую глубину сразу в расстояние. Промежуточная перспективная
   глубина upstream теряла точность: в GPU-тесте 90 000 000 м превращались в 78 125 000 м.
5. Облака и воздушная перспектива находятся в одном `EffectPass`. Это предотвращает чтение depth-текстуры,
   одновременно прикреплённой к выходному framebuffer при MSAA=0. Overlay композируется один раз.
6. Смена положения камеры и качества пересоздаёт историю облаков; изменение размера обновляет все буферы.
7. Единственный объект лаборатории — сфера Юпитера. Для её отсечения облачный проход использует точное пересечение луча
   со сферой. Чтение ближайшего пикселя растровой глубины при разных разрешениях проходов ошибочно обрезало слой на больших
   расстояниях. Этот специальный путь **нельзя переносить в сцену с кораблями/другими объектами без учёта их глубины**.
8. Расстояние появления управляет премультиплицированными RGB и alpha overlay одновременно и ослабляет оптическую глубину
   теней. При нулевом вкладе пропускается весь `CloudsEffect.update`, включая тени. При повторном включении история очищается.
9. Объёмные и поверхностные тени затухают в последних 20% дальности каскадов. Дальний каскад больше не затеняет точки
   за пределами покрытия, проявляя прямоугольный край. После скачка камеры, изменения Солнца и повторного включения
   первый кадр теней берётся целиком из текущих данных, затем возобновляется временное накопление.

Шейдерные адаптеры намеренно привязаны к указанным версиям; при изменении точек замены они сообщают об ошибке.
При обновлении Takram проверить их заново, особенно после перехода upstream на WebGPU/TSL.

## Проверки

```sh
npm exec -- vitest run tests/clouds
npm run typecheck
npm run lint
npm run build
```

Для GPU-проверки оставить Vite работающим на 8086 и выполнить:

```sh
npm run test:clouds:gpu
```

Нужен установленный Chromium/Chrome/Edge. Нестандартный путь задаётся `CHROME_BIN`, URL лаборатории —
`CLOUD_LAB_URL`. Скрипт запускает отдельный headless-профиль, проверяет WebGL-ошибки, пять видов,
разницу кадров с облаками и без них, смену качества/освещения/размера и освобождение сцены.
`tests/clouds/planetDepth.gpu.ts` выполняет настоящий фрагмент декодирования глубины в float32,
показывая ошибку upstream и проверяя исправленный вариант. Снимки и результат — в `tmpscreenshots/cloud-lab/`.
`tests/clouds/cloudOcclusion.gpu.ts` растеризует сферу, проверяет ошибочное отсечение лучей облачного слоя соседними пикселями
и отсутствие такого отсечения в аналитическом варианте. GPU-прогон также проверяет неизменность орбитального изображения
при переключении облаков и остановку облачных проходов после выхода из ближней зоны.

## Границы эксперимента

- Пока используется отдельная композиция Takram; основной `AtmosphereEffect` TitanEngine ещё не изменён.
- Полосы и вихри исходной карты сохранены вдали. Объёмная плотность пока не согласована с этой картой; перенос рисунка
  и цвета поясов в объём, вращение и ветровая анимация — следующий этап.
- Слой и погода стационарны; сферическая форма не учитывает сплюснутость Юпитера.
- Для джиттера используется локально сгенерированный белый шум. Он грубее STBN; заметны шум и временные артефакты.
- Ближний вид существенно дороже орбитального, особенно на встроенной графике. Настройки — начальные.
- Результат подтверждает пригодность рендерера для дальнейшей работы; качество полного покрытия и полёта
  ещё нужно доводить перед включением в обычный сценарий Солнечной системы.
