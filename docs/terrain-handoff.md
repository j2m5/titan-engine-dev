# Террейн: статус и продолжение (хендофф)

Шпаргалка для продолжения работы без контекста прошлой сессии. Актуальна на 2026-08-14, master `9967144`.

## Большая картина

Идём по одобренному роадмапу процедурных поверхностей каменистых планет. Полные спеки лежали в `docs/superpowers/` (гитигнорено — на этой машине их может не быть), ключевые решения продублированы здесь.

**Роадмап (одобрен владельцем):** кубосфера + квадродерево патчей 65×65, честный CPU-мешер (вершины двигает только CPU — коллизия и рендер зовут одну функцию высоты, GPU только шейдит подсеточную деталь), единая `h(dir̂)` = карта высот + процедурные октавы с fade ниже разрешения карты. RTC-вершины обязательны: ulp float32 на 75 000 юнитов (1 AU) больше Эвереста. Этапы: 0 данные → 1 честные высоты на статичной сфере → 2 `TerrainHeightField` + коллизия камеры с рельефом → 3 кубосфера-каркас (SSE, скирты, RTC) → 4 глубокий LOD + процедурка (вымышленные тела) → 5 TerrainMaterial (сплаттинг, трипланар) → 6 ground-level (Worker, тайлы, вода, Земля — вне скоупа). Решения владельца: низкий полёт сейчас с масштабированием до ground-level; гибрид DEM+процедурка; океаны и Земля позже; пилот — Луна.

## Сделано (влито в master, запушено)

**Коллизии камеры** (пререквизит, 2026-08-13): `src/core/services/CameraCollision.ts` — свип со скольжением + пуш-аут по сферам тел; ЧД намеренно без коллизий; `COLLISION_GAP = 1.001` — задел под рельеф (станет функцией направления на этапе 2).

**Террейн этапы 0+1** (2026-08-14, коммиты `f10bddc..dea571f` + `9967144`):
- `src/core/terrain/heightMapFormat.ts` — формат карты: raw Uint16 + 24-байт заголовок TEHM (magic, версия, w, h, minMeters f32, maxMeters f32, LE), строка 0 = север.
- `scripts/build-heightmap.ts` + `scripts/lib/{heightMapEncode,resampleDem,rawDem}.ts` — оффлайн-конвейер DEM → TEHM. Два входа: GeoTIFF/PNG (sharp) и сырой PDS IMG int16 LE (`--in-width/--in-height/--scale-meters`, area-average даунсемпл).
- Тип ресурса `height` (`src/core/models/types.ts`), строка БД Луны (resource 125, actorResource 114, actorId 19, путь `planets/moon/moon_height.raw`). Гарды: height ВСЕГДА `resident` (streamable с неизвестным расширением роняет TextureProvider и откатывает все ресурсы актора), отфильтрован из резидентного текстурного пути (`ResourceObserver.setResidentTextures`).
- `src/core/services/HeightFieldStorage.ts` — модульный синглтон, fetch карт с S3 мимо текстурного конвейера, ДО построения сцены (`Application.run`); провал = warn + гладкая сфера.
- `src/core/terrain/heightSampling.ts` — `sampleHeightMeters` (билинейка, wrap долготы, кламп полюсов) + `buildDisplacedSphere` (1024 сегмента, r = R + h, нормали из градиента карты с честными арками и гардом полюсов; НЕ computeVertexNormals — шов).
- `src/core/renderables/Planet.ts` — ветка рельефа при наличии карты в реестре; иначе легаси байт-в-байт. `PlanetMaterial` подавляет USE_BUMP у тел с height-ресурсом (двойной учёт рельефа).
- vitest: exclude `**/.claude/**` в `vite.config.ts` — иначе прогон из корня захватывает копии тестов в git-worktree'ях.

**Slope-карта: попиксельный рельеф** (2026-08-15, ветка `feature/terrain-slope-shading`): приёмка этапа 1 нашла регрессию — зерно у терминатора и мыло издалека. Корень (замерен): вершинные нормали брали градиент ±1 тексель на сетке с шагом 8 текселей — алиасинг (шум/сигнал 0.84), плюс потеря попиксельной 8K-детали старого bump-пути. Лечение: нормали смещённой сферы радиальные, весь наклон шейдится попиксельно slope-картой с мипами. Конвейер: `scripts/lib/slopeMapEncode.ts` + `npm run build:slopemap` (TEHM → WebP lossless 8192×4096: R — уклон на восток, G — на север, байт 128 = 0, диапазон ±SLOPE_RANGE из `src/core/terrain/slopeMapFormat.ts` — константа общая с GLSL-декодом; арки честные с cos широты по полутексельной GPU-конвенции; у полюсов базис восточной разности расширен до метрической длины экваториальной пары текселей — иначе 1/cos усиливал квантование высот в сатурированный шум). Новый тип ресурса `slope`; `SlopeNormal.ts` чанк (USE_SLOPE); `PlanetMaterial` гейтит USE_SLOPE по фактически загруженной карте в HeightFieldStorage (провал загрузки высот = гладкая сфера БЕЗ кратерного шейдинга, а не враньё поверх); строка БД 48 → slope `planets/moon/moon_slope.webp`, bumpScale Луны = 1 (физически честный дефолт). Заметка этапа 2 про «мёртвый стриминг moon_bump» закрыта этим же ходом.
Принятые риски финального ревью: (а) пока slope-карта стримится/выгружена, рельеф Луны освещается гладко — окно совпадает с окном стриминга диффуза того же актора, отдельного лечения не имеет; (б) квантование уклонов 0.9°/шаг — уклоны положе 0.45° кодируются нулём; если терминатор покажет постеризацию на морях, лечить дизером в энкодере или сужением SLOPE_RANGE.

**Террейн этап 2: коллизия камеры с рельефом** (2026-08-15, ветка `feature/terrain-stage2-collision`): `src/core/terrain/TerrainHeightField.ts` — канонический владелец высот тела; мешер (`buildDisplacedSphere`) и коллизия (`CameraCollision`) зовут одну и ту же функцию `heightMeters(dir̂)`. `dirToUv` побайтно совпадает с развёрткой SphereGeometry (закреплено паритетным тестом), тексели центрованы на полутекселях — канонизация приняла GPU-конвенцию (`(i+0.5)/N`, как texture2D и slope-энкодер), CPU-сэмплер больше не расходится с шейдерным. Карта провиса (clearance grid, блоки 8×8 вершинных ячеек, дилатация 3×3 + запас `CLEARANCE_MARGIN_METERS`) гарантирует, что визуальная сетка нигде не проваливается под честную высоту. Коллизия: `Collider.heightField?` — широкая фаза по сфере `R+maxH+maxClearance`, узкий пуш-аут камеры по `R+h(dir̂)+clearance(dir̂)` в теле-фиксированном фрейме (учитывает вращение тела), свип — рэймарч со скольжением по нормали градиента карты (не радиальной). `RELATIVE_CONTACT_EPSILON` в `CameraCollision` заменил абсолютный `CONTACT_EPSILON` — эпсилон контакта масштабируется от радиуса тела, а не фиксированные 1e-6. Замер прохода карты провиса (критерий приёмки №3, `TerrainHeightField` на `moon_height.raw`): типично ~205 мс, `maxClearanceMeters` 8424 м — на грани терпимого порога спеки ~200 мс, но однократно при старте (кешируется через `terrainHeightFieldFor`, не на кадр); офлайн-перенос вычисления вне скоупа этапа 2.
Закрытые заметки этапа 2: полутексельная конвенция канонизирована на GPU-полутекселях в `TerrainHeightField` (см. выше); `CONTACT_EPSILON` стал относительным. Заметка о брутфорс-рейкасте (клик по Луне, 2.1М треугольников) остаётся открытой — терпим до квадродерева этапа 3.

## Ближайший шаг — руками (после него Луна обрастёт рельефом)

1. Скачать **LDEM_64.IMG** (530 МБ, public domain): https://imbrium.mit.edu/DATA/LOLA_GDR/CYLINDRICAL/IMG/LDEM_64.IMG
2. Положить например в `storage/images/textures/` (гитигнорено правилом `**/textures/`) и сконвертировать:
   ```
   npm run build:heightmap -- --in storage/images/textures/LDEM_64.IMG --out storage/images/textures/moon_height.raw --in-width 23040 --in-height 11520 --scale-meters 0.5
   ```
3. Залить результат (67 МБ) в Яндекс-бакет: `textures/planets/moon/moon_height.raw`.
4. Собрать slope-карту и залить её в бакет (`textures/planets/moon/moon_slope.webp`, lossless, ~21 МБ):
   ```
   npm run build:slopemap -- --in public/images/textures/planets/moon/moon_height.raw --out public/images/textures/planets/moon/moon_slope.webp --radius-meters 1737400
   ```
   **Не деплоить до заливки обоих файлов**: стример катит ресурсы актора всё-или-ничего — 404 на slope-карте откатит и диффуз, Луна останется плейсхолдером.
5. Визуальная проверка: рельеф на лимбе и терминаторе Луны, кратеры ловят свет, нет шва по меридиану и артефактов на полюсах; терминатор без зерна, деталь сопоставима со старым bump-путём; при рассинхроне рельефа с диффузом по долготе — пересобрать со сдвигом. Земля/Марс не изменились. Камера пока садится на сферу R×1.001, не на рельеф — это норма до этапа 2.

## Следующий этап разработки — этап 3

Кубосфера-каркас: квадродерево патчей 65×65 вместо статичной сферы 1024 сегмента, экранно-пространственная ошибка (SSE) для выбора уровня детализации, скирты на границах патчей разного LOD (иначе трещины по стыкам), RTC-вершины (Relative-to-Camera) обязательны — ulp float32 на 75 000 юнитов (1 AU) больше Эвереста, честной геометрии на дальних телах без RTC не будет. Мешер и коллизия уже зовут единый `TerrainHeightField.heightMeters(dir̂)` (этап 2) — кубосфере остаётся расставлять патчи и решать, где какой LOD, высоты не переоткрывать. Заметки, которые надо учесть в спеке этапа 3:
- Само смещение вершин берётся точечно с шагом 8 текселей карты (на сетке 1024 сегмента) и слегка алиасит (в силуэте — субпиксель); при переходе на патчи 65×65 с переменным шагом решить, нужен ли префильтр h(dir̂) под текущий шаг сетки патча.
- Клик-рейкаст по Луне brute-force 2.1М треугольников — терпим до квадродерева, но с патчами переменного LOD рейкаст нужно продумывать заново (какой уровень детализации трассировать).
- Ловушка `PlanetMaterial`: define'ы USE_* не удаляются при повторном updateMaterial (сброс только в resetMaterial).
